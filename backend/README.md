# iPhotos Backend

.NET 10 backend for iPhotos — a local-first photo gallery with a React Native mobile app.
An Immich-style trusted server: uploads with SHA-256 dedup, **EXIF metadata indexing in
PostgreSQL**, **image variants** (original / preview / thumbnail) generated by a
**dedicated worker**, and **email + password auth (Argon2id + JWT)**.

Built with TDD — `dotnet test` runs 209 tests (unit + integration against real
PostgreSQL/MinIO-style containers via Testcontainers; requires Docker to be running).

## Projects

| Project | Role |
|---|---|
| `iPhotos.Domain` | Entities and invariants (User, Photo, PhotoVariant, VariantJob, RefreshToken) |
| `iPhotos.Application` | Use cases, abstractions (repositories, IBlobStorage, IImageVariantGenerator), DTOs |
| `iPhotos.Infrastructure` | EF Core + Npgsql, migrations, repositories, blob storage clients (filesystem + HTTP) |
| `iPhotos.Imaging` | Variant generation (ImageSharp) and EXIF extraction |
| `iPhotos.Auth` | Argon2PasswordHasher + JwtTokenService |
| `iPhotos.Core` | HTTP API host (endpoints, DI, JwtBearer auth, rate limiting) |
| `iPhotos.Worker` | BackgroundService processing the `variant_jobs` queue (SKIP LOCKED) |
| **`iPhotos.Storage`** | **Pluggable object storage library: FileSystem, S3-compatible (AWS S3/Wasabi/MinIO/B2/R2), WebDAV, Google Drive + SSRF guard, signed URLs** |
| **`iPhotos.Storage.Host`** | **Standalone storage HTTP API: PUT/GET/DELETE objects → URLs (presigned or HMAC-signed)** |
| `tests/*` | Unit tests per project + HTTP integration tests with Testcontainers |

## API

| Method | Route | Description |
|---|---|---|
| POST | `/api/auth/register` | `{email, password, displayName?}` → tokens |
| POST | `/api/auth/login` | `{email, password}` → tokens |
| POST | `/api/auth/refresh` | `{refreshToken}` → tokens (rotation) |
| POST | `/api/auth/logout` | revokes the refresh token `[auth]` |
| POST | `/api/photos` | multipart `file` (jpeg/png/webp) → creates photo + job; hash dedup `[auth]` |
| GET | `/api/photos` | paginated listing: `from,to,fileName,camera,page,pageSize` `[auth]` |
| GET | `/api/photos/{id}` | metadata + variants `[auth]` |
| DELETE | `/api/photos/{id}` | removes photo + variants + blobs `[auth]` |
| GET | `/api/photos/{id}/files/{kind}` | `original|preview|thumbnail` (streaming) `[auth]` |
| GET | `/api/usage` | used bytes vs quota `[auth]` |
| GET | `/health` | liveness |

Error mapping: 400 validation · 401 credentials/token · 404 not found ·
409 duplicate email · 413 quota exceeded · 429 rate limit.

## Running

```bash
# everything (postgres + api + worker), migrations applied on api startup:
docker compose up --build

# API at http://localhost:5205 ; OpenAPI at /openapi/v1.json (dev)
```

Without Docker: a local PostgreSQL (connection string in
`iPhotos.Core/appsettings.json`) and `dotnet run --project iPhotos.Core` +
`dotnet run --project iPhotos.Worker`.

## Storage service (iPhotos.Storage.Host)

Blob storage is decoupled from the API: `iPhotos.Storage.Host` is a standalone
"send bytes → get URL" service, and the api/worker talk to it over HTTP
(`BlobStorage:Mode=Http`). The compose stack starts it on `127.0.0.1:5206`
and its filesystem provider keeps objects in the `storage-data` volume.

Contract (all mutating endpoints require `X-Api-Key`; erros como `{ error }`):

| Method | Route | Description |
|---|---|---|
| PUT | `/api/objects/{key}?provider=` | raw body → 201 `{url, key, provider, sizeBytes, contentType, expiresAt}` (overwrites) |
| GET/HEAD | `/api/objects/{key}` | stream (Range ok) — auth via `X-Api-Key` **or** signed URL (`?exp=&sig=`) |
| DELETE | `/api/objects/{key}` | 204, idempotent |
| POST | `/api/objects/url?key=&expirySeconds=` | fresh signed GET URL for an existing object |
| GET | `/api/providers` | configured providers (no secrets) |
| GET | `/health` | liveness |

URLs returned on upload are consumable **without** the API key: S3-family
providers return SigV4 presigned GETs; filesystem/WebDAV/Google Drive return
HMAC-signed URLs scoped to method+provider+key+expiry. Object keys are opaque
`[A-Za-z0-9._-]` segments separated by `/` (the api keeps using
`{owner}/{photo}/original.jpg` etc.).

### Storage backends & configuration (`iPhotos.Storage.Host/appsettings.json`)

```jsonc
{
  "Storage": {
    "DefaultProvider": "filesystem",   // filesystem | s3 | webdav | googledrive
    "ApiKey": "required-in-prod",      // X-Api-Key for management calls
    "SigningKey": "32-bytes-minimum",  // HMAC for signed URLs
    "PublicBaseUrl": "",               // baked into signed URLs; default = request host
    "UrlExpiry": "7.00:00:00",
    "AllowPrivateNetworks": false,     // true for MinIO/compose/LAN endpoints (SSRF guard)
    "RedirectToPresigned": false       // 302 to presigned URL on S3-family GETs
  },
  "Providers": {
    "FileSystem": { "RootPath": "data/objects" },
    "S3": {
      "Endpoint": "",                  // "" = AWS; or Wasabi/MinIO/B2/R2 endpoint
      "Region": "us-east-1",
      "Bucket": "", "AccessKey": "", "SecretKey": "",
      "ForcePathStyle": true,          // required by Wasabi/MinIO/B2/R2
      "Prefix": ""                     // optional key prefix inside the bucket
    },
    "WebDav":  { "BaseUrl": "", "RootPath": "", "Username": "", "Password": "", "TimeoutSeconds": 100 },
    "GoogleDrive": { "ServiceAccountJsonPath": "", "ServiceAccountJson": "", "RootFolderId": "" }
  }
}
```

Every value maps to an env var via `__` (e.g. `Providers__S3__Bucket`).

### Bucket setup — AWS S3

1. S3 Console → **Create bucket** → unique name, region of choice, **Block all
   public access: ON** (the service uses signed requests; nothing public).
2. Bucket versioning: optional (recommended for recovery); encryption: SSE-S3 default.
3. IAM → **Create user** (programmatic) → policy scoped to the bucket:

```json
{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Effect": "Allow",
      "Action": ["s3:PutObject", "s3:GetObject", "s3:DeleteObject"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET/*"
    },
    {
      "Effect": "Allow",
      "Action": ["s3:ListBucket", "s3:GetBucketLocation"],
      "Resource": "arn:aws:s3:::YOUR_BUCKET"
    }
  ]
}
```

4. Config: `Endpoint=""`, `Region=bucket-region`, `Bucket`, keys, `ForcePathStyle=false`.

### Bucket setup — Wasabi

1. Console → **Buckets → Create Bucket** (region e.g. `eu-central-2`), public access off.
2. **Access Keys → Create Access Key** (keys are account-wide; scope by bucket policy if desired).
3. Config: `Endpoint=https://s3.<region>.wasabisys.com`, `Region=<region>`,
   `ForcePathStyle=true`.

### MinIO (self-hosted)

```bash
docker run -d --name minio -p 9000:9000 \
  -e MINIO_ROOT_USER=iphotos -e MINIO_ROOT_PASSWORD=<secret> minio/minio server /data
docker run --rm --network host minio/mc sh -c \
  "mc alias set local http://localhost:9000 iphotos <secret> && mc mb local/iphotos"
```

Config: `Endpoint=http://<host>:9000`, `ForcePathStyle=true`, `AllowPrivateNetworks=true`.

### Backblaze B2

1. Create a **Bucket** (private) → **App Keys → Add Application Key** (scope to the bucket;
   note the *keyID* as AccessKey and the *applicationKey* as SecretKey; the key's endpoint
   is shown as e.g. `s3.us-west-004.backblazeb2.com`).
2. Config: `Endpoint=https://s3.<region>.backblazeb2.com`, `Region=us-west-004`,
   `ForcePathStyle=true`.

### Cloudflare R2

1. Dashboard → R2 → **Create bucket** (location hint any) → **Manage R2 API Tokens →
   Create API token** (Object Read & Write, scope to the bucket) → note
   Access Key ID / Secret Access Key and the **S3 endpoint**
   (`https://<accountid>.r2.cloudflarestorage.com`).
2. Config: that endpoint, `Region=auto`, `ForcePathStyle=true`.

### WebDAV (Nextcloud, Hetzner Storage Box, generic)

Config: `BaseUrl=https://cloud.example.com`, `RootPath=remote.php/dav/files/<user>/iphotos`
(Nextcloud; Storage Box: empty RootPath), `Username`/`Password` (Nextcloud: app password).
Collections are created automatically per key segment.

### Google Drive (service account)

1. Google Cloud Console → enable **Google Drive API** → create a **Service account** →
   JSON key (download).
2. A service account has **no personal quota**: create a folder inside a **Shared Drive**,
   share it with the SA e-mail (Content manager), and put the folder id in `RootFolderId`.
3. Config: `ServiceAccountJsonPath` (or inline `ServiceAccountJson`), `RootFolderId`.
   Files are always proxied through this host (private Drive files are not hotlinkable).

### Backend (api/worker) storage mode

| Env | Meaning |
|---|---|
| `BlobStorage__Mode` | `Filesystem` (default) or `Http` |
| `StorageService__BaseUrl` | e.g. `http://storage:8080` (compose) |
| `StorageService__ApiKey` | must match the storage service `Storage__ApiKey` |
| `StorageService__Provider` | optional provider override per request |
| `StorageService__AllowPrivateNetworks` | `true` when BaseUrl is LAN/compose-internal |

In `Http` mode the api and worker no longer need a shared volume: original reads for
variant generation go over HTTP, and the database keeps blob keys only.

## Conventions

- **Time**: everything is UTC (`IDateTimeProvider.UtcNow`, `DateTimeOffset` with zero
  offset, `timestamptz`).
- EXIF has no timezone: `DateTimeOriginal` is interpreted as UTC.
- Variants: thumbnail 320px q75 · preview 2048px q80 (no upscaling, EXIF orientation
  respected). Videos: Original keeps the file as-is (never transcoded) and
  Preview/Thumbnail are the ffmpeg-extracted poster frame (JPEG).
- Accepted upload formats: photos JPEG/PNG/WebP (HEIC arrives via zip import, where
  the server transcodes it) and videos MP4/M4V/MOV/WEBM/AVI/3GP. Video metadata and
  poster extraction require **ffmpeg/ffprobe** — installed in the api/worker Docker
  images; locally set `VideoProcessor:FfmpegPath`/`FfprobePath` if not on PATH.
- ImageSharp is pinned to **3.1.x**: starting with 4.0 the package requires a license
  key for Release/Docker builds (`sixlabors.lic`, free via
  [sixlabors.com/pricing](https://sixlabors.com/pricing/)).
  To use 4.x, get the license and remove the pin.
- The `users` table already stores opaque E2E fields (`wrapped_master_key`, `kdf_salt`,
  `kdf_params`) so a future zero-knowledge mode (app plan 03) can coexist.
